# Settings reference

## Where settings come from

The API reads its settings in layers. Each layer overrides the one before:

1. `src/WebBase.Api/appsettings.json`: defaults, committed to git. **No secrets here.**
2. `appsettings.Development.json`: development-only logging tweaks.
3. **Environment variables.** `Section__Key` sets `Section:Key` (two
   underscores). This is how Docker and every cloud host configure the app.

On your computer, environment variables come from `.env.local`, through the
compose files:

```
.env.local            compose.dev.yaml / compose.prod.yaml        the API sees
JWT_KEY=abc...   ──▶  Jwt__Key: ${JWT_KEY}                   ──▶  Jwt:Key = abc...
```

`.env.local` is created by `./setup.sh`, ignored by git, and readable only by
you (`chmod 600`). `.env.example` is its committed template, with every line
explained.

## .env.local

| Setting | Used by | Meaning |
|---|---|---|
| `APP_NAME` | dev, prod | The site's name in the header and tab |
| `JWT_KEY` | prod (dev optional) | Signs sign-in tokens. Generated by setup. Changing it signs everyone out |
| `POSTGRES_PASSWORD` | prod | The database owner's password. Fixed once prod's database exists |
| `POSTGRES_APP_PASSWORD` | prod | The app's own database password. Fixed once prod's database exists |
| `PROD_DATABASE_URL` | prod | A managed database for prod, instead of the container. Empty = container ([DEPLOYING.md](DEPLOYING.md#a-managed-database)) |
| `GOOGLE_CLIENT_ID` | dev, prod, cloud | Turns on Google sign-in ([GOOGLE_SIGNIN.md](GOOGLE_SIGNIN.md)) |
| `AUTHOR_EMAILS` | dev, prod, cloud | Emails that become authors when they sign in with Google. Optional ([AUTHORS.md](AUTHORS.md)). Not for `cloud.env`, which is public: set it in the shell that runs the cloud script, or in `.env.local` |
| `CMS_ENABLED` | dev, prod, cloud | `true` turns on the CMS ([CMS.md](CMS.md)) |
| `CMS_SOURCE` | dev, prod, cloud | Where its files are: `files` (`content/`, the default), `s3`, `azure` or `gcs`, each a module to add first ([CMS.md](CMS.md#where-the-content-lives)) |
| `CMS_S3_*`, `CMS_AZURE_*`, `CMS_GCS_*` | dev, prod, cloud | The bucket or container, for `s3` / `azure` / `gcs`. The keys and connection string among them are secrets, and the cloud scripts don't copy them ([CMS.md](CMS.md#in-a-cloud)) |
| `CLOUDFLARE_TUNNEL_TOKEN` | `./tunnel.sh` | The tunnel to your domain ([CLOUDFLARE_TUNNEL.md](CLOUDFLARE_TUNNEL.md)) |
| `DEV_WEB_PORT` | dev | Website port, default 5173 |
| `DEV_API_PORT` | dev | API port (for tools; the browser doesn't need it), default 5000 |
| `DEV_DB_PORT` | dev | Database port, default 5432 |
| `PROD_PORT` | prod | Production's port on this computer, default 8080 |
| `AZURE_DATABASE` | cloud scripts | `cosmos` (the Azure free setup's default; its free tier never expires) or `postgres` ([AZURE.md](AZURE.md#the-database-cosmos-db-or-postgresql)) |
| `BUILD_MODULES` | cloud scripts | Override the modules the image is built with, e.g. `cosmos azure` ([MODULES.md](MODULES.md)). Normally chosen from the database and `CMS_SOURCE` |
| `GCP_TIER`, `AZURE_TIER`, `AWS_TIER` | cloud scripts | `free` (default) or `standard` (always on, bigger, costs money): [GOOGLE_CLOUD.md](GOOGLE_CLOUD.md), [AZURE.md](AZURE.md), [AWS.md](AWS.md) |
| `GCP_*`, `AZURE_*`, `AWS_*` | cloud scripts | Region, project, your own database (`*_DATABASE_URL`), and so on: the top of each script in `scripts/cloud/` lists them. They can go in `cloud.env` too, except the database address, which is a secret |

### cloud.env: settings for the cloud, committed

`cloud.env` holds the same **public** settings (`APP_NAME`, `GOOGLE_CLIENT_ID`,
`CMS_*`) for cloud deploys, and is committed. That's what lets a deploy from
GitHub Actions, or a change made from Claude Code on the web, set them: edit
it, push, and the next deploy applies it ([GOOGLE_CLOUD.md](GOOGLE_CLOUD.md#changing-settings)).
A value in the environment or in `.env.local` wins over it. The cloud scripts
refuse to run if anything in it looks like a secret (a name with `KEY`,
`SECRET`, `PASSWORD`, `TOKEN`, `CONNECTION_STRING` or `DATABASE_URL`, with a value).

Running two projects made from this template on one computer? Give the
second one different ports, for example `DEV_WEB_PORT=5174`,
`DEV_API_PORT=5001`, `DEV_DB_PORT=5433`, `PROD_PORT=8081`.

## The API's settings

| Setting (environment variable) | Default | Meaning |
|---|---|---|
| `App__Name` | WebBase | Display name |
| `App__Environment` | *(empty = prod)* | `development` shows the dev banner and the API docs at `/scalar`, and allows a missing `Jwt__Key` |
| `App__Build` | | The release id. Baked in by the Dockerfile |
| `Jwt__Key` | | **Required outside development.** At least 32 characters. The app refuses to start without it |
| `Jwt__LifetimeDays` | 30 | How long a sign-in lasts without a visit |
| `Jwt__Issuer`, `Jwt__Audience` | WebBase | Names written into tokens. Rarely changed |
| `DATABASE_URL` | | `postgres://user:pass@host:port/db?sslmode=require`. Takes priority over the next one. Locally, `PROD_DATABASE_URL` in `.env.local` sets it for prod |
| `ConnectionStrings__Default` | local dev database | .NET-style connection string for requests |
| `ConnectionStrings__Migration` | | If set, migrations run on this connection (the owner role in prod) |
| `Database__Provider` | postgres | Which database implementation to use ([DATABASE.md](DATABASE.md)). `postgres` by default; `cosmos` once the app is built with that module ([MODULES.md](MODULES.md)) |
| `Database__MigrateOnStartup` | true | Get the database ready when the app starts (Postgres: apply new migrations) |
| `Auth__Google__ClientId` | | Google sign-in; empty = off |
| `Auth__AuthorEmails` | empty | Emails (comma or space separated) that become authors at a Google sign-in. The first account is an author anyway. Env: `AUTHOR_EMAILS` ([AUTHORS.md](AUTHORS.md)) |
| `Cms__Enabled` | false | The CMS ([CMS.md](CMS.md)) |
| `Cms__Source` | files | `files`, or a file storage module the app is built with: `s3`, `azure`, `gcs` |
| `Cms__ContentPath` | `../../content` | For `files`: the folder. Docker sets this (`/src/content` in dev, `/app/content` in the image) |
| `Cms__RefreshSeconds` | 60 | How often to look for changed content; 0 = every request (development) |
| `Cms__S3__Bucket`, `__Prefix`, `__Region`, `__ServiceUrl`, `__AccessKey`, `__SecretKey` | | For `s3`. `ServiceUrl` for S3-compatible services; without keys, the standard AWS credentials ([CMS.md](CMS.md#s3-and-s3-compatible-storage)) |
| `Cms__Azure__ContainerUrl`, or `__ConnectionString` + `__Container`; `__Prefix` | | For `azure`. A URL without a SAS token signs in with the app's identity ([CMS.md](CMS.md#azure-blob-storage)) |
| `Cms__Gcs__Bucket`, `__Prefix` | | For `gcs`. Signs in as the app's own service account ([CMS.md](CMS.md#google-cloud-storage)) |
| `RateLimits__AuthPerMinute` | 10 | Sign-in/sign-up attempts allowed per visitor per minute |
| `RateLimits__ClientIpHeader` | | A header that says who the visitor is, for when every request arrives from a proxy that isn't a normal load balancer. `compose.prod.yaml` sets `CF-Connecting-IP` for the Cloudflare tunnel. Leave it empty elsewhere: a header anyone can send would let a flood choose its own address |
| `Abuse__Enabled` | on in prod, off in development | The request limits below |
| `Abuse__PerIpPerMinute` | 240 | More requests than this from one address in a minute bans it (a page load is 10-30). Env: `ABUSE_PER_IP_PER_MINUTE` |
| `Abuse__BanMinutes` | 30 | How long a ban lasts. Env: `ABUSE_BAN_MINUTES` |
| `Abuse__TotalPerMinute` | 6000 | All addresses together, per running copy of the app. Past it, requests get a quick 503 for the rest of the minute, so a flood from many addresses has a ceiling. 0 = none. Env: `ABUSE_TOTAL_PER_MINUTE` |
| `Abuse__MaxBodyKb` | 256 | The biggest request body accepted. Env: `ABUSE_MAX_BODY_KB`. Keep it at 240 or more: the longest page an author can save is about that big ([PAGES.md](PAGES.md#rules)); the app warns at startup if it is lower |
| `PORT` | | If set (by a cloud host), listen on this port instead of 8080 |

## Adding a setting

Say your feature needs an API key for a mail service:

1. **appsettings.json**: add the section, with an empty value:
   `"Mail": { "ApiKey": "" }`
2. **Read it in C#**: `builder.Configuration["Mail:ApiKey"]`. Or make an
   options class like `GoogleAuthOptions` in `Infrastructure/Options.cs`,
   register it with `builder.Services.Configure<MailOptions>(config.GetSection("Mail"))`,
   and ask for `IOptions<MailOptions>` in a constructor.
3. **.env.example**: add `MAIL_API_KEY=` with a comment (this documents it for the next person).
4. **.env.local**: add your real value.
5. **compose.dev.yaml and compose.prod.yaml**: under the `api` / `app`
   service's `environment:`, add `Mail__ApiKey: ${MAIL_API_KEY:-}`.
6. **Cloud**: add `Mail__ApiKey` wherever your host takes secrets. For the
   scripted clouds, add it next to `Jwt__Key` in `scripts/cloud/<cloud>.sh`.

**Settings the website needs** (a public key, a feature switch) go out through
`GET /api/config` (`Controllers/ConfigController.cs`) and are read in
`client/src/stores/config.ts`. Never put a secret there: anyone can read it.
